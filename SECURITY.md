# Security reporting

Please report suspected vulnerabilities privately so they can be assessed without exposing users. Do not post exploit details, credentials, or private data in public issues, discussions, or pull requests.

## Report a vulnerability

Email [team@xo.builders](mailto:team@xo.builders?subject=Security%20report) with the subject **Security report**. If the affected repository's **Security → Advisories** page offers **Report a vulnerability**, you can use that private GitHub form instead.

Include what you know:

- The affected repository or service, and version or commit if available.
- A description of the issue and its possible impact.
- Minimal steps or a proof of concept that demonstrate the problem safely.
- Relevant logs or screenshots with credentials and personal data removed.
- A way to contact you with follow-up questions.

Use your own test accounts and data. Avoid accessing other people's data, disrupting services, or running tests beyond what is needed to demonstrate the issue. Do not send live credentials or unnecessary private content.

## Follow-up and disclosure

Keep sensitive details in the private report while we assess the issue and discuss remediation and disclosure. If you have additional evidence or a proposed disclosure date, include it in the same conversation.

Repository-specific security policies take precedence over this shared policy. For ordinary setup problems or bugs without a security impact, use our [support routes](https://github.com/quirq-ai/.github/blob/main/SUPPORT.md).
